# IDV-ASAS 用户使用说明

## 1. 环境准备

### 1.1 系统要求

| 项目 | 要求 |
|------|------|
| 操作系统 | Linux（需图形界面，WSL2 需配置 WSLg） |
| Rust 工具链 | cargo 1.75+（建议 1.97+） |
| 屏幕 | 1280×720 窗口化显示 |
| 网络 | 需访问模型 API 服务 |
| 模型接口 | 任意 OpenAI 兼容的 `chat/completions` 服务 |

### 1.2 编译与运行

```bash
cd app
cargo run --release
```

首次编译需要联网拉取依赖，之后可离线运行。

### 1.3 资源目录要求

程序需要项目根目录下存在以下结构：

```
IDV-ASAS/
├── app/                    # 程序目录
│   ├── Cargo.toml
│   └── src/
├── resources/              # 后端数据资料
│   ├── AGENTS.md
│   ├── README.md
│   ├── characters/         # 角色数据
│   └── maps/               # 地图数据
├── icons/                  # 前端图标资源
│   ├── maps/               # 地图概念图
│   ├── area-selection/     # 区域选点底图
│   ├── characters/         # 角色头像（原始 120×120）
│   ├── personas/           # 天赋图标
│   └── positions/          # 选点坐标数据
└── DICTIONARY.md           # 中英文字典
```

## 2. 完整使用流程

### 第 0 步：配置 API 接口

启动程序后首先进入配置界面。

**情况一：已有默认配置**

程序检测到 `app/config.json` 存在时，会显示当前配置摘要（端点、模型、温度、单价），并询问"是否沿用默认配置？"

- 点击 **是**：直接沿用，进入下一步
- 点击 **否**：进入配置编辑表单

**情况二：无默认配置**

直接显示配置编辑表单，需依次填写：

| 字段 | 说明 | 示例 |
|------|------|------|
| API Base URL | 服务商前缀，填到 `/v1` 即可 | `https://api.deepseek.com/v1` |
| API Key | 以 `Bearer` 方式携带的密钥（隐藏显示） | `sk-xxxxxxxx` |
| 模型名称 | 由服务商决定 | `deepseek-chat` |
| 温度 temperature | 0~2 之间，默认 0.7 | `0.7` |
| max_tokens | 输出长度限制，留空 = 不限制 | `4096` |
| 输入 token 单价 | 人民币元 / 每百万 tokens | `2` |
| 输出 token 单价 | 人民币元 / 每百万 tokens | `8` |

填写完成后，勾选"保存为默认配置"（默认勾选），点击 **确认**。

> ⚠️ **安全提示**：`config.json` 中 API Key 为**明文存储**，请勿将该文件提交到代码仓库或分发给他人。

### 历史会话导入

配置完成后，若 `app/history/` 目录下存在历史记录，程序会询问"是否导入历史会话？"

- 点击 **是**：展示历史列表（含模型、局数、累计 Token、费用、全局需求摘要），点击列表项选择导入
- 点击 **否，直接新开**：跳过导入，开始全新会话

导入后全局需求自动继承，直接进入第 2 步（地图选择），无需重新输入全局需求。界面顶部会显示 `✓ 已导入历史会话（共 N 局记录）` 提示。

### 第 1 步：输入全局用户需求

在文本框中输入全局需求。全局需求对本会话的每一局均生效。

例如：`队伍需要携带两个化险为夷，优先保护羸弱角色。`

- 若无全局需求，可直接点击 **确定**
- 输入完成后点击 **确定** 进入下一步

### 第 2 步：选择当局地图

界面展示 3×3 的地图概念图网格，按字典顺序排列共 9 张排位地图：

| 军工厂 | 圣心医院 | 红教堂 |
|--------|---------|--------|
| 湖景村 | 月亮河公园 | 里奥的回忆 |
| 永眠镇 | 唐人街 | 不归林 |

- 点击地图图片进行选择，被选中的地图以**黄色高亮框**标识
- 再次点击同一地图可取消选择
- 点击其他地图可切换选择
- 选定地图后点击 **确认** 进入角色选择

### 第 3 步：选择当局角色

界面分为上下两部分：

**上方：角色选择网格**

- 按 `DICTIONARY.md` 顺序排列共 51 名角色
- 每页 18 格（6 列 × 3 行，先填左半 9 格从上到下从左到右，再填右半 9 格），共 3 页
- 左下角 ◀ / 右下角 ▶ 为翻页按钮
- 点击角色头像进行选择，被选中的角色以**黄色高亮框**标识
- 再次点击可取消选择
- 选满 4 个角色后，其余角色头像置灰并禁用点击

**下方：已选角色展示 + 确认按钮**

- 四个已选角色头像及中文名横向排列成一行
- 取消选择时自动从列表移除
- 选满 4 个角色后，**确认** 按钮变为可用

### 第 4 步：输入当局用户需求

在文本框中输入仅对当前这局生效的特殊需求。

例如：`本局医生想打野，不要放安全点。`

- 若无当局需求，可直接点击 **确定**
- 输入完成后点击 **确定**，开始调用模型分析

### 第 5 步：调用模型进行分析

程序显示加载动画和"正在调用模型进行分析……"提示，同时显示当前模型与端点信息。

此过程中可随时点击 **打断** 按钮停止分析。

- 若分析正常完成，自动进入结果展示
- 若分析被打断，进入错误界面，可选择重试或退出
- 若接口调用失败，进入错误界面，可选择重试、重新输入或退出

### 第 6 步：展示模型分析结果

结果展示界面采用左右布局：

**左侧：区域选择展示**

- 显示当前地图的区域选点底图
- 将 4 名角色的头像按推荐选点位置合成叠加在地图上
- 每个角色头像上方标注选点编号

**右侧上：天赋选择展示**

- 分 4 行，每行显示一个角色的头像及推荐的两个天赋图标
- 图标旁标注角色名（黄色）、天赋名称（白色）、选点编号（灰色）

**右侧中：分析与说明**

- 显示模型对该方案的具体描述与分析（不超过 100 字）

**右侧下：翻页与确认**

- 使用 ◀ / ▶ 按钮在多个推荐方案间切换
- 点击 **确认使用** 锁定当前方案，进入对局等待

### 第 7 步：等待对局结束

界面保持锁定在已确认的方案展示页面。**对局结束** 按钮替换确认使用按钮。完成游戏对局后，点击 **对局结束** 按钮。

程序将显示：
- 本局 Token 用量（输入 + 输出 = 总计）
- 本局费用（按单价计算）
- 本次会话累计统计

### 第 8 步：是否开启下一对局

- 点击 **是**：返回第 2 步（地图选择），全局需求保留不重新输入
- 点击 **否**：进入历史保存界面

### 历史保存（退出前）

程序会询问"是否保存本次会话历史？"

- 点击 **保存**：进入命名界面
  - 输入名称后点击 **确认保存**：以该名称保存
  - 留空点击 **确认保存**：以当前时间（如 `20260905-003530`）命名
  - 点击 **取消**：返回保存询问
- 点击 **不保存**：直接退出程序

## 3. 配置详解

### 3.1 config.json 格式

```json
{
  "base_url": "https://api.deepseek.com/v1",
  "api_key": "sk-xxxx",
  "model": "deepseek-chat",
  "temperature": 0.7,
  "max_tokens": null,
  "price_input_per_m": 2.0,
  "price_output_per_m": 8.0
}
```

- `max_tokens` 为 `null` 表示不限制
- 可手动编辑此文件修改配置（注意 JSON 格式）
- API Key 为明文，请妥善保管

### 3.2 兼容的服务商

任意 OpenAI 兼容的 `chat/completions` 接口均可使用，包括但不限于：

| 服务商 | Base URL | 模型示例 |
|--------|----------|---------|
| OpenAI | `https://api.openai.com/v1` | `gpt-4o-mini` |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` |
| SiliconFlow | `https://api.siliconflow.cn/v1` | `deepseek-ai/DeepSeek-V3` |
| 自建网关 | `http://localhost:8080/v1` | 自定义 |

### 3.3 端点规范化

程序自动处理 Base URL 的格式差异：
- 输入 `https://api.xxx.com/v1` → 补全为 `.../v1/chat/completions`
- 输入 `https://api.xxx.com/v1/chat/completions` → 不重复追加

## 4. 方案输出格式

模型返回的每套方案严格遵循以下格式：

```
方案 1：
5 号选点：佣兵：回光返照、化险为夷
2 号选点：古董商：回光返照、飞轮效应
6 号选点：作曲家：回光返照、膝跳反射
8 号选点：空军：回光返照、化险为夷
具体描述及分析：前锋利用中场板窗承担抗压牵制，医生置于安全的小树林稳定破译，整体均衡。
```

- **选点行**：`x 号选点：角色名：天赋1、天赋2`
- **描述行**：以 `具体描述及分析：` 开头，不超过 100 字，使用俗称而非编号
- 每套方案 6 行：1 行编号 + 4 行选点 + 1 行描述
- 不包含前言、思考推理过程或总结

## 5. Token 用量与费用统计

- 数据来源优先为接口返回的 `usage` 字段（精确值）
- 若服务商不返回 `usage`，则按字符数 × 0.75 估算，并标注"按字符估算"
- 单价填 0 时费用显示 ¥0.0000，tokens 仍正常统计
- 每局确认完成后显示本局用量与费用，以及会话累计

## 6. 常见问题

| 问题 | 处理方法 |
|------|---------|
| `接口返回错误 HTTP 401` | API Key 错误或未填写 |
| `HTTP 400 temperature参数非法` | 温度已自动四舍五入到 2 位小数；若仍报错，检查 config.json |
| `HTTP 404` | Base URL 填错，应形如 `https://域名/v1` |
| `Connection refused / 超时` | 网络不通或地址端口错误 |
| `等待模型响应超时` | 120 秒未收到任何输出，检查网络或模型服务状态 |
| 想更换模型 | 下次启动在第 0 步选择"否"重新配置，或手动编辑 config.json |
| 想修改全局需求 | 新会话重新输入；或手动编辑 history/ 下对应 JSON 的 global_req 字段后加载 |
| 误点了打断 | 在错误界面点击"重试"即可重新生成 |
| 模型输出不合规 | 程序会自动重试 3 次；若持续不合规，提示"您的模型与该项目不适配" |
| 窗口关闭时未保存 | 程序会拦截关闭请求，弹出历史保存询问 |

## 7. 历史记录管理

### 7.1 文件位置

历史记录保存在 `app/history/` 目录下，为普通 JSON 文件。

### 7.2 手动维护

- **查看**：用文本编辑器打开任意 `.json` 文件即可查看内容
- **备份**：复制 JSON 文件到其他位置
- **删除**：直接删除不需要的 JSON 文件
- **重命名**：重命名文件即可，文件名即显示名称

### 7.3 续局说明

加载历史会话后：
- 全局需求与累计统计自动继承
- 局数从上次中断处继续
- 可修改 API 配置（如换模型续开）
- 历史局以紧凑形式进入上下文，避免 Token 膨胀

## 8. 注意事项

1. 窗口固定为 1280×720，未做分辨率兼容适配。
2. 所有展示文字均为中文。
3. 鼠标用于选择操作，键盘用于文本输入（需求、命名等）。
4. `app/config.json` 和 `app/history/` 为运行产物，建议加入 `.gitignore`。
5. API Key 明文存储于 config.json，请注意保管。
6. eframe 仅启用 X11 后端（禁用 Wayland），WSL2 环境需确保 X11 库已安装。
